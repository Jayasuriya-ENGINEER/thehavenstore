# Promo-code Firestore rules review

## Access pattern

- `promoCodes/{UPPERCASE_CODE}` is read by a signed-in shopper through an exact
  document-id lookup at checkout.
- Only the authenticated, hard-coded administrator account lists or mutates promo documents.
- Customer read access is `get` only, so promo codes cannot be enumerated.

## Data model

Each promo document has an immutable `code` and `createdAt`, a `discountType`
(`percent` or `amount`), a positive bounded `discountValue`, an `expiresAt`
timestamp, an `active` boolean, and `updatedAt` timestamp. The code is also
the document ID to prevent mismatched lookups.

## Review outcome

The new collection uses separate `get` and `list` permissions, validates the
full document on both creation and update, protects immutable identity fields,
and grants all writes only through the existing admin authority check. Promo
values are rechecked at checkout, while the displayed total is clamped so
discounts cannot reduce the product subtotal below zero.
